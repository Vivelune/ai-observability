# 0004. SDK event contract conventions

Status: accepted (draft: rewrite in your own words)
Date: 2026-11-10

## Context

The event schema is the contract between our SDK, our ingest API and Team B's emitters. Several SDK versions will be in the wild at once, clients can fail and retry, and prices for models change after data is stored.

## Decision

- Timestamps are ISO-8601 strings in UTC with a `Z` suffix.
- All IDs, including `event_id`, are UUIDs generated by the client.
- Events have a small envelope (`schema_version`, `event_id`, `event_type`, `sent_at`) and the entity under `data`.
- `tenant_id` is never accepted from the client.
- Cost is computed on the server from a pricing table.
- Versioning is MAJOR.MINOR with a tolerant reader: additive changes only within a major.
- Oversized LLM input and output are truncated at 100 KB, not rejected.

## Alternatives considered

- Epoch milliseconds: compact, but unreadable in logs and easy to confuse with seconds.
- Server-generated IDs: simpler to trust, but a span could not be sent before its parent finishes and retries would create duplicates.
- Client-computed cost: avoids a pricing table, but a wrong price would need an SDK release across every client.
- Rejecting oversized payloads: strict, but loses the whole trace over one long prompt.

## Consequences

Retries are safe because of `event_id`, and out-of-order delivery works. Prices can be corrected and recomputed later. We must keep a pricing table, a dedupe path and a recompute job, and any breaking change needs a major version and a notice to Team B.
